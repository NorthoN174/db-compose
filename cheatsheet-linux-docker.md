Шпаргалка: Linux + Docker + Git + PowerShell

Рабочий конспект. Всё, что здесь есть, я уже запускал сам и понимаю, что оно делает. Правило номер один: сначала смотрю, потом меняю.

1. Где я и что здесь
Команда	Что делает
whoami	под каким пользователем я сижу
pwd	в какой папке я сейчас
ls -la	что в папке: подробно, вместе со скрытыми файлами
cat файл	показать содержимое файла (.env не показывать: там пароли)
cat /etc/os-release	версия Ubuntu
uname -r	версия ядра
clear	очистить экран
Как читать права в ls -la

drwxr-x---: первая буква d папка или - файл, дальше три тройки rwx для владельца, группы и всех остальных (r читать, w писать, x запускать/входить). Точка в начале имени значит «скрытый файл».

2. Сеть
Команда	Что делает
hostname	имя машины
hostname -I	все IPv4-адреса (там же адреса Docker-мостов, они не нужны)
ip -br a	адреса по интерфейсам: eth0 настоящий, docker0 и br-... мосты Docker, veth... «кабели» контейнеров
ip route get 1.1.1.1	каким адресом машина выходит наружу: смотреть после слова src

Как найти нужный адрес на новой машине: ip route get 1.1.1.1, адрес после src. Он должен быть в той же подсети, что и мой компьютер.

3. Docker
Команда	Что делает
docker ps -a	все контейнеры, и работающие, и остановленные
docker volume ls	диски (тома)
docker network ls	сети
docker compose config --quiet	проверка compose-файла на ошибки (молчит, если всё в порядке)
docker compose up -d	поднять весь стек в фоне
docker compose ps	состояние стека
docker compose logs --tail 15 имя_сервиса	последние 15 строк журнала сервиса
docker compose down	остановить и удалить контейнеры и сети (диски остаются)

Осторожно: docker compose down -v удаляет ещё и диски, то есть данные базы. Без крайней нужды не использовать.

Как устроены файлы проекта
Dockerfile: рецепт сборки образа (как эталонный образ ОС).
docker-compose.yml: схема, какие контейнеры поднять, какие сети, диски, порты и в каком порядке.
.env: настройки и пароли. Всегда в .gitignore.
Схема стека db-compose
браузер → nginx (порт 80) → python_app (порт 5000) → postgres
          [frontend]        [frontend + backend]       [backend]
frontend и backend это две изолированные сети, как две VLAN.
python_app стоит в обеих, это «шлюз» между ними.
Сервисы находят друг друга по имени из compose (postgres, python_app), а не по IP.
Наружу открыты только порт 80 (nginx) и 8080 (Adminer).
Подводные камни, которые уже встречались
external: true у диска значит, что диск должен существовать заранее: docker volume create pg-data.
Пароль Postgres применяется только при первом создании диска. Сменил пароль в .env, а диск старый, и будет password authentication failed.
Adminer открыт на все адреса (0.0.0.0:8080). Правильнее 127.0.0.1:8080:8080.
Контейнер работает от root и создаёт файлы с владельцем root в моей папке. Отсюда проблемы с правами.

5. PowerShell (Windows и Active Directory)

Команды называются Глагол-Существительное. Результат передаётся дальше через |. Всегда одна и та же цепочка из четырёх блоков:

источник → фильтр → порядок → вывод

powershell
Get-ADUser -Filter 'Enabled -eq $true' -Properties WhenCreated |   # источник
  Where-Object { $_.WhenCreated -lt $limit } |                     # фильтр
  Sort-Object WhenCreated |                                        # порядок
  Select-Object Name, WhenCreated                                  # вывод
$_ это текущая строка, $_.Свойство это столбец.
-eq равно, -lt меньше, -gt больше, -and и, -or или.
Посчитать результат: ( ...команда... ).Count.
Пустое значение ($null) PowerShell считает «меньше любой даты». Фильтр обязательно проверять подсчётом: до и после.
В свойство в фильтре подставлять то, что запросил в -Properties.
6. Привычки и безопасность
Сначала смотрю (ls, cat, ps, config, Get-...), потом меняю (Set-, Remove-, rm, down, prune).
Пароли и токены: только в .env, который в .gitignore. Никому не показывать, в чат вставлять только с xxx.
Только имена переменных из .env, без значений: cut -d= -f1 .env.
Рабочие выгрузки со списками людей с собой не уносить.
PuTTY: выделил мышью значит скопировал. Ctrl+C там прерывает команду.
Подключение к серверу, когда нет лицензий RDS: mstsc /v:сервер /admin.
